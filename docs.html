The HHT.js guide

Build from the
DOM up.

HHT.js is a lightweight JavaScript framework for creating DOM elements, handling events, managing state, and following URL hash routes.

It favors readable JavaScript and small, explicit steps. Its abstractions are simple enough to study, while supporting a working TodoMVC application.

01 / Start here

Getting started

HHT.js is source code in this repository, with no separate framework package to install. A view is a function that returns a virtual node: a plain description of an element. render() turns that description into browser DOM.

↗
The key idea

Describe what the page should look like now. When data changes, call render() again with a fresh description.

Quick start

Save this as app.js in the project root. Use the separate app.html shell in Project setup below; it loads /app.js and includes the matching <div id="app"></div>. 

import { createElement, render } from "./framework/index.js";

const greeting = createElement("h1", { class: "greeting" }, [
  "Hello, HHT.js!",
]);

render("#app", greeting);

The browser receives a real heading: <h1 class="greeting">Hello, HHT.js!</h1>.

03 / Start here

Importing HHT.js

The public entry point is framework/index.js. It provides seven named exports. Import only the functions your file uses; the relative path depends on where that file lives. 

// From a file in the project root:
import { createElement, render, state } from "./framework/index.js";

// From a file inside todo/:
// import { createElement, render, state } from "../framework/index.js";

There is no default export or hht.div() namespace. Framework modules also export internal helpers, so application code should import from framework/index.js. Short examples below assume the named functions they use have been imported from this entry point.

04 / Building UI

Creating elements

createElement(tag, attrs, children) builds a virtual node. It does not create browser DOM until you pass that node to render() or mount(). The tag is an HTML tag name; attributes are an object; children are one value or an array. 

const heading = createElement("h1", {}, ["Hello"]);
const paragraph = createElement("p", {}, ["A short explanation."]);
const button = createElement("button", { type: "button" }, ["Save"]);
const input = createElement("input", {
  type: "text",
  placeholder: "Your name",
});

const card = createElement("div", { class: "card" }, [
  heading,
  paragraph,
  button,
  input,
]);

The card description renders as a div containing a heading, paragraph, button, and input. There are no built-in tag shortcuts: use createElement("div", ...) for a div.

05 / Building UI

Attributes & styles

Pass HTML attribute names in the second argument. Use class and for, not JavaScript property names such as className. Values of null or undefined remove an attribute on a later render. 

const field = createElement("input", {
  id: "task-name",
  class: "field",
  type: "text",
  placeholder: "Add a task",
  value: "Read the guide",
  disabled: false,
});

const checkbox = createElement("input", {
  type: "checkbox",
  checked: true,
});

checked, disabled, selected, and muted also sync their DOM properties on each render. For a boolean HTML attribute, false, null, or undefined removes it. A string such as "false" still leaves the attribute present and therefore on.

Inline styles

style accepts a CSS string or an object of DOM style property names. Object values do not get units added automatically. 

createElement("p", {
  style: { color: "#0d9488", marginTop: "16px" },
}, ["Ready to build."]);

createElement("p", {
  style: "color: #0d9488; margin-top: 16px",
}, ["The same style as a string."]);

key and ref are special HHT.js attributes. Keys identify siblings during list updates; a ref callback receives a DOM element after rendering and null when tracked content is removed.

06 / Building UI

Child elements

Pass nested virtual nodes in the third argument to create an HTML tree. Nested arrays are flattened, so map() results fit naturally into a child list. 

const names = ["Ada", "Lin", "Sam"];

const list = createElement("ul", { class: "names" }, [
  names.map((name) =>
    createElement("li", { key: name }, [name]),
  ),
]);

This produces one ul with three li elements. Give each sibling a stable, unique key when rendering a changing list. HHT.js uses keyed updates when every sibling in the old and new lists has a key. Keys are not written as HTML attributes.

07 / Building UI

Text & conditional children

Strings and numbers become text nodes. Nested arrays are flattened, while null, undefined, and boolean children are omitted. This makes conditional content straightforward. 

const count = 3;
const showTip = true;

const summary = createElement("section", {}, [
  createElement("h2", {}, ["Tasks"]),
  "Remaining: ",
  count,
  showTip ? createElement("p", {}, ["Keep going!"]) : null,
]);

0 is a valid text child. For conditional elements, prefer a ternary or a condition that produces null; items.length && node would render 0 when the array is empty. Function children are not a reactive feature and fail when rendered.

08 / Building UI

Events

Use an on… attribute to let HHT.js attach a native DOM event listener. The handler receives the normal browser event; event.target, event.key, and event.preventDefault() work as usual. 

createElement("button", {
  onClick: (event) => {
    console.log("Clicked", event.currentTarget);
  },
}, ["Click me"]);

createElement("input", {
  onInput: (event) => console.log(event.target.value),
  onChange: (event) => console.log("Committed", event.target.value),
  onKeydown: (event) => {
    if (event.key === "Enter") console.log("Submitted");
  },
});

Other native events work the same way: onSubmit, onBlur, and onDblclick are useful examples. onInput follows each text edit; onChange follows the browser’s native change event. A normal function handler receives its element as this. HHT.js lowercases the part after on: onDblclick and onDblClick both map to dblclick; onDoubleClick maps to the wrong event. Handler values must be functions, null, or undefined.

Events outside the rendered tree

The public on() helper handles window, document, and other event targets. It returns a function that removes that listener. 

import { on } from "./framework/index.js";

const stopListening = on(window, "resize", () => {
  console.log(window.innerWidth);
});

// Call when this listener is no longer needed:
stopListening();
09 / State

State management

state(initialValue) returns an object with get(), set(), and subscribe(). Subscribers are called synchronously whenever set() runs. An updater function receives the current value and returns the next value. 

const count = state(0);
count.get();                    // 0
count.set(1);                   // replace the value
count.set((current) => current + 1); // 2

const stop = count.subscribe((value) => {
  console.log("Count changed:", value);
});

count.set(3); // logs "Count changed: 3"
stop();       // removes this subscription

A subscription does not run when created. set() notifies even if the new value equals the old one; HHT.js does not compare values. For arrays and objects, return a new value when updating so your own code can reason clearly about changes. 

const todos = state([{ id: 1, text: "Read", completed: false }]);

todos.set((items) => [
  ...items,
  { id: 2, text: "Build", completed: false },
]);

todos.set((items) => items.map((item) =>
  item.id === 1 ? { ...item, completed: true } : item,
));
10 / State

Rendering behavior

render(target, node) owns one root node inside the target. On the first call it creates DOM. On later calls it compares the old and new virtual nodes, updating changed text, attributes, event handlers, and children. Compatible elements can stay in place; stable keys help preserve list items when they move.

User event→state.set()→Subscriber runs→render()→DOM updates

The framework does not automatically connect state to rendering. Register your render function as a subscriber, then call it once to draw the initial page: 

const count = state(0);

function view() {
  return createElement("p", {}, ["Count: ", count.get()]);
}

function renderApp() {
  render("#app", view());
}

count.subscribe(renderApp);
renderApp();

Calling render() with a new tree is the update step; changing a virtual node or its attributes in place is not a supported update pattern.

11 / State

Mounting the application

Start an app by selecting an existing container and calling render() for its first view. The target can be a CSS selector string or a DOM element. If a selector is invalid or finds nothing, HHT.js throws an error. 

import { createElement, render, unmount } from "./framework/index.js";

render("#app", createElement("main", {}, ["Ready"]));

// When the app should be removed:
unmount("#app");

mount(target, node) is also public. Each call appends another node and does not track updates. Use it for static content. Use render() for a stateful app. unmount() empties the target and clears any tracked render tree; it does not cancel state subscriptions or listeners created with on().

12 / Routing

Routes

createRouter() makes a hash router. Its app URLs look like /#/ and /#/about; the route lives after #. Register exact paths, subscribe your render function, then start the router. 

import { createElement, createRouter, render } from "./framework/index.js";

const router = createRouter();
router.register("/").register("/about");

function page(path) {
  return path === "/about"
    ? createElement("h1", {}, ["About"])
    : createElement("h1", {}, ["Home"]);
}

function renderApp() {
  render("#app", router.getCurrentView(page));
}

router.subscribe(renderApp);
router.start();
renderApp();

getCurrentView(page) calls page(path) for a registered route. Unknown paths return the router’s built-in 404 view. Route matching is exact and case-sensitive; there are no route parameters or path patterns.

13 / Routing

Navigation

Use router.navigate("/about") or a regular hash link. router.getCurrentRoute() reads the current normalized path. Browser back and forward navigation fires hashchange; a started router updates its subscribers. Continuing the router example above: 

router.subscribe((path) => {
  console.log(path, router.getCurrentRoute());
});
router.navigate("/about"); // subscriber logs after hashchange

const link = createElement("a", { href: "#/" }, ["Home"]);
#
Two different routes

This documentation page is served at the real pathname /docs. HHT.js routing is for hash paths such as /#/about inside an application page.

14 / Examples

Complete counter example

Save the following as counter.html and counter.js in the project root. Open /counter.html through the dev server. The click handler updates state, the subscription calls renderApp(), and HHT.js updates the text in the DOM. 

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>HHT.js counter</title>
    <script type="module" src="/counter.js"></script>
  </head>
  <body><div id="app"></div></body>
</html>
import { createElement, render, state } from "./framework/index.js";

const count = state(0);

function Counter() {
  return createElement("main", { class: "counter" }, [
    createElement("h1", {}, ["Counter"]),
    createElement("p", {}, ["Count: ", count.get()]),
    createElement("button", {
      type: "button",
      onClick: () => count.set((current) => current + 1),
    }, ["Add one"]),
    createElement("button", {
      type: "button",
      onClick: () => count.set(0),
    }, ["Reset"]),
  ]);
}

function renderApp() {
  render("#app", Counter());
}

count.subscribe(renderApp);
renderApp();

The initial renderApp() matters because subscribe() only reacts to future set() calls.

15 / Examples

Small todo app

This smaller example keeps todos in an array, adds one on Enter, and toggles completion. Save it as todo-example.js and use the counter HTML shell above with src="/todo-example.js". The project’s full TodoMVC adds editing, filters, and persistence. 

import { createElement, render, state } from "./framework/index.js";

const todos = state([]);
let nextId = 1;

function addTodo(event) {
  if (event.key !== "Enter" || event.isComposing) return;
  const text = event.target.value.trim();
  if (!text) return;
  event.target.value = "";
  todos.set((items) => [
    ...items,
    { id: nextId++, text, completed: false },
  ]);
}

function toggleTodo(id) {
  todos.set((items) => items.map((item) =>
    item.id === id
      ? { ...item, completed: !item.completed }
      : item,
  ));
}

function TodoApp() {
  return createElement("main", {}, [
    createElement("h1", {}, ["My todos"]),
    createElement("input", {
      placeholder: "Add a task and press Enter",
      onKeydown: addTodo,
    }),
    createElement("ul", {}, todos.get().map((todo) =>
      createElement("li", { key: todo.id }, [
        createElement("input", {
          type: "checkbox",
          checked: todo.completed,
          onChange: () => toggleTodo(todo.id),
        }),
        " ", todo.text,
      ]),
    )),
  ]);
}

function renderApp() {
  render("#app", TodoApp());
}

todos.subscribe(renderApp);
renderApp();
16 / Reference

Public API reference

The entry point exports exactly these seven named functions. The methods returned by state() and createRouter() are described with their parent functions below.

createElementDescribe an element → renderShow and update a view → mountAppend static content → unmountClear a target → stateHold a value → createRouterFollow hash routes → onListen to events →

createElement(tag, attrs?, children?)

Purpose. Describe an HTML element without touching the DOM. 

createElement("p", { class: "note" }, ["Hello"]);
Parameters
tag (string): HTML tag name. attrs (object, default {}): attributes, events, style, key, or ref. children (value or array, default []): text, numbers, virtual nodes, or nested arrays.
Returns
A plain virtual-node object with tag, attrs, and normalized children.
Notes
Only the third argument supplies children; extra child arguments are ignored. null attributes cause a render error.

render(target, node)

Purpose. Render one root virtual node and patch that target on later calls. 

render("#app", createElement("p", {}, ["Updated view"]));
Parameters
target (CSS selector string or DOM element): existing container. node (virtual node, string, or number): new root content.
Returns
undefined.
Notes
Call after state changes; state does not call it automatically. A single root occupies the container.

mount(target, node)

Purpose. Append a node to an existing container. 

mount("#app", createElement("p", {}, ["Static note"]));
Parameters
target (CSS selector string or DOM element): container. node (virtual node, string, or number): content to append.
Returns
undefined.
Notes
Each call appends another node, and these appends are not tracked for future patching. Prefer render() for an app that updates.

unmount(target)

Purpose. Empty a container and clear its tracked render history. 

unmount("#app");
Parameters
target (CSS selector string or DOM element): container to clear.
Returns
undefined.
Notes
Tracked refs from render() receive null. Content added with mount() is cleared, but its refs are not tracked for cleanup.

state(initialValue)

Purpose. Store a value and notify subscribers when it is set. 

const score = state(0);
const stop = score.subscribe((value) => console.log(value));
score.set((previous) => previous + 1);
console.log(score.get()); // 1
stop();
Parameters
initialValue (any type): starting value.
Returns
An object with get(): value, set(valueOrUpdater): undefined, and subscribe(listener): unsubscribe function.
Notes
set() calls subscribers synchronously for every update. subscribe() does not invoke its listener immediately.

createRouter()

Purpose. Create a router based on the URL hash. 

const router = createRouter();
router.register("/").register("/about");
router.subscribe((path) => console.log("Route:", path));
router.start();
router.navigate("/about");
Parameters
None.
Returns
A router with register(path): router, navigate(path): undefined, start(): undefined, getCurrentRoute(): string, getCurrentView(renderRoute): view result, and subscribe(listener): unsubscribe function.
Notes
Register paths before starting. getCurrentView() returns the view callback’s result, or a built-in 404 node for unknown routes. Refresh and browser history use the hash.

on(target, eventName, handler, options?)

Purpose. Register a native event listener and receive its cleanup function. 

const stop = on(window, "keydown", (event) => {
  if (event.key === "Escape") console.log("Closed");
});
stop();
Parameters
target (EventTarget): object with add/remove listener methods. eventName (nonempty string): native event name. handler (function): receives the native event. options (optional): passed to browser listener methods.
Returns
An idempotent function that removes the listener.
Notes
Use on… attributes for events on HHT.js elements. on() is useful for global or outside-tree listeners.
17 / Concepts

Framework concepts

01

DOM abstraction

createElement() makes a description of UI. render() translates it into real DOM and compares later descriptions.

02

State

state() stores values. Your view reads with get(); event handlers write with set().

03

Events

onClick and similar attributes give the framework a callback to run when a native event fires.

04

Routing

A router reads location.hash, tracks the current path, and asks your route view function for a page.

These pieces remain explicit: you decide which state and route changes call your render function. That wiring is visible in the counter and routing examples.

18 / Concepts

Inversion of control

With a library, your application calls a helper whenever it needs one. A framework also calls your application code at the right moment. HHT.js does this when an event fires, a state subscriber is notified, a hash route changes, or a ref becomes available.

01You provide a callbackcount.subscribe(renderApp)
↓
02The framework stores itstate.set(nextValue)
↓
03The framework calls yourenderApp()

HHT.js keeps this relationship small and visible. You still choose the callbacks and connect them; the framework handles when to invoke them and how to update its rendered DOM.

19 / Help

Common mistakes & troubleshooting

My page is blank after creating state.

state.set() does not render automatically. Subscribe your render function and call it once for the initial view: store.subscribe(renderApp); renderApp();

HHT.js says the mount target was not found.

Check that your selector matches an element already in the page. Load the app module after the target exists or place the module script in the document head with type="module".

My nested children or list do not appear.

Pass all children as the third argument, usually an array. createElement("div", {}, [first, second]) works; separate fourth and fifth child arguments are ignored.

My click handler never runs.

Use a native event spelling such as onClick or onDblclick, and pass a function. onClick: save() runs save during view creation; use onClick: save or an arrow function.

My route shows a 404 page.

Register the exact path before rendering it. HHT.js routes live in the hash, for example #/about, and route matching is case-sensitive.

Can I use functions as reactive children?

No. Use state.subscribe(renderApp) and let the view read the latest state during each render. Function children are not valid renderable nodes.

Why does mount() not update my app?

mount() only appends once. Use render() for the initial view and subsequent updates.
